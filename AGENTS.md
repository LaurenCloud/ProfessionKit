# ProfessionKit

WoW Forever addon, interface 16001. User's sketch defines the layout: left profession navigation, middle recipe list with search and ranking controls, right inputs → requirements → output and crafting controls.

The sketch defines structure, not a flat visual theme. Use WoW's native frame/button templates, game textures, gold headings and standard fonts. Harness previews approximate spacing and must not be presented as screenshots of native artwork.

Selected profession and recipe tabs, their connectors, the workspace and the detail panel share the same opaque near-black neutral fill (0.055 per RGB channel), using the native WHITE8X8 texture. Keep native borders and gold selection outlines; the window background, navigation, inactive rows and inset controls retain their native textures. Flat matching fills make the selected tabs and connected contents one continuous surface.

Keep the layout compact and content-sized. Recipe tiles always show the native item/recipe icon, skill-up icon, count and name on top, with left-aligned estimated skillups and right-aligned total/each coin prices below, without a dot separator. Sort buttons only change ordering, never the displayed information. Recipe tiles use 8-unit horizontal padding and 58-unit height. The selected recipe joins the detail panel with the same tab connector as profession navigation; keep text columns fixed, hide the connector when the selection is scrolled away, and extend the detail panel behind low selected rows. Do not reserve space for absent skill-up icons. Measure the full unbounded quantity text and round its width up with a small allowance; never truncate the bracketed count. No footer or slogan. Show actual known auction-price age in the detail header over the price columns. No cost-per-craft or margin line. A native gold minimap quest arrow, rotated downward, links materials to output without a hammer or requirement label; unmet station/tool requirements replace crafting controls with one red message and disappear when controls return.

Use a shared 12-unit inset around panels. Recipe tiles have smaller 6-unit gaps. The compact search uses a 6-unit inset and an internal placeholder. Sort choices are small inset buttons labelled Sort. The × Quantity checkbox, default checked, multiplies ranking by available crafts; unchecked ranks one craft. Never hide recipes based on materials. Persist the checkbox choice. Row counts, skillup estimates and total/each prices continue to describe available materials. Keep the columns compact; long recipe lists should scroll sooner on smaller screens instead of shrinking the text. Use `est.` for estimates, not a tilde, which renders poorly in the game's font.

Group matching recipes in Pinned, Recipes, Camping order. Pinned regular and Camping recipes rank together under both sorts and quantity settings. Save pins by recipe ID. Unpinning restores the original group. Use the client's Camping category. Show gold-yellow headings for visible groups with an extra 8-unit gap between groups. Omit the heading for a regular-only list. Default to the first matching row and preserve explicit selections on refresh.

Within each section, sort first by the selected full-precision score, then by available craft quantity descending, then by recipe name and ID. Unknown auction prices remain below known prices. Give the bracketed quantity its own color: green when materials are available, red at zero. Recipe-name color and native skill-up arrows represent skill difficulty independently. Keep the existing `est. N skillups` text; the user declined a separate `no skillups` label.

Keep Blizzard's trade-skill session alive while hiding its visual window. Craft only on an explicit user click, revalidate profession, recipe, materials, requirements and combat at that moment. Never auto-buy, post or share messages. Preserve native window fallback.

Craft ordinary recipes through a direct C_TradeSkillUI.CraftRecipe(recipeID, count) call on the hardware-click path. Enchant equipment through C_TradeSkillUI.CraftEnchant(recipeID, 1, nil, targetLocation) on the same path. Do not wrap these actions in pcall/xpcall or schedule them. Observe rejection via client events; only spellcast-start confirms crafting, and matching spellcast-success events complete a batch. Watchdog timers must be tied to their request and must never craft. Keep native enchant-overwrite confirmation; a pending REPLACE_TRADESKILL_ENCHANT or REPLACE_ENCHANT popup suspends the start watchdog without inventing cast progress.

Enchant recipes show a target item slot and the client-provided effect instead of an output item with sale prices. Clicking the slot opens bags; dropping an eligible item selects it, and right-click clears it. The Equipped picker only lists eligible worn items. Use the native GetEnchantItems eligibility list and track a target's GUID, resolving and revalidating its current carried/equipped ItemLocation on the craft click. Never substitute another copy with the same item ID, move/equip the selected item, or bypass native confirmations. Retain targets for repeat enchants. Trade-window enchants, disenchanting/salvage and reagent-choice recipes retain Original window fallback.

Honor canCreateMultiple, HasNoReagentCost, disabled/craftable and disabledReason from the client. Hide all batch controls for single-cast recipes and equipment enchants; reject invalid counts again on click. Cap batches by remaining charges. Read the profession cooldown API with its charge semantics, falling back to C_Spell cooldown/charge data when necessary, excluding the global cooldown. Show remaining cooldown duration and refresh it while visible.

Station badges belong beside the rank on each left profession tab, with native station art, green borders when a station is nearby and desaturated/dim art otherwise. Use named SpellFocus requirements from learned recipes; carried tools and area restrictions are not station badges. Retain only representative recipe IDs per station in SavedVariables, never proximity values. Query proximity afresh while visible, with the native profession-focus API for ordinary stations before recipes have loaded. Unknown data is distinct in the tooltip and never retains a stale green state. Include advanced stations in the tooltip and record station-state changes in bounded diagnostics. Gold outlines continue to mean selection.

The watchdog must respect native queued recasts between individual casts. A confirmed batch requires two separated idle observations before a silent stop; overdue timers start a fresh observation window so background throttling cannot beat queued cast events. Missing queue APIs fall back to the same idle grace. Real interruption/failure events still end the request immediately. Record timer recovery and queue state in diagnostics; never infer completed craft counts from elapsed time.

Left-clicking the minimap icon always opens ProfessionKit. Right-click opens settings with a persistent replace-normal-window checkbox, defaulting on only when unset. Changes apply to the next normal profession open; an explicit original-window fallback lasts for that session only.

Use live C_TradeSkillUI data and Auctionator read-only APIs. Unknown prices are not zero. Vendor purchase prices and vendor sale values are distinct. Label skill ranking as heuristic when no exact chance is available. Show Create all total duration from spell cast time; refine total and remaining time from the live matching cast timestamps. Omit unknown timing rather than inventing a duration.

Quantity +/- buttons use native UIPanelSquareButton artwork, not squeezed wide red buttons, with fixed-size centered glyphs. Active crafting has its own textured, gold-bordered panel anchored to the bottom right of the workspace, separated from the selected recipe details and never overlapping their tab connector. Its fixed-height layout always shows the active recipe's name and icon, captured when the batch starts. It stays visible when browsing other professions, other recipes, unmet requirements or empty search results. This panel contains only the one active batch: no scrolling, history or second queued job. Hide the entire panel when no batch is active. Idle duration previews and failures belong to the selected recipe details.

Allow profession navigation while crafting through direct OpenTradeSkill on the hardware click, never by casting a profession's spellbook ability. Capture the crafting profession independently of the browsed profession, keep Create disabled until the current batch ends, and avoid reopening an already-selected live source. Trade-skill source-close and recipe-less repeat-stop events do not prove the active spell ended; retain the request until matching spell events or the existing queue-aware idle watchdog resolve it. Diagnostics must distinguish browsed and crafting identities. Native queue survival through direct profession switches still needs in-game verification; simulated event handoffs cannot establish it.

During confirmed crafting, center the remaining time in white with a dark shadow on the native gold progress bar. The bar is 28 units tall, leaving 7 units above and below its 14-unit countdown text; center it vertically beside the batch count and estimated total time. Progress covers the whole batch using the same timing model as the estimate; update its visual smoothly without rescanning recipes or initiating crafts. Hide the bar while starting without confirmation or missing timing, while keeping the active batch status visible.

K and the menu button share ToggleProfessionsBook. Route that entry point to the remembered profession when replacement is enabled, including the first use after reload before any profession data is open. Preserve disabled replacement and explicit native fallback. Validate cold opens with Blizzard_Professions unloaded.

No unit tests. Validate full addon loading and user workflows with the integration runner and retain its report. Actual client behavior must be reported separately. Deploy with scripts/deploy.ps1, which backs up existing addon files. Source here is authoritative; do not edit only the installed copy.

Keep the main window width fixed. Use compact automatic height until the user drags the bottom-right grip. Persist the preferred height in UI units and derive list capacity from usable height. Fit recipe details, profession tabs and the active batch panel before applying the preference. Temporary content or screen limits must preserve the saved height.

When the recipes overflow, fill the recipe column down to its range counter and clip partial rows at the viewport edges. Include partly visible recipes in the range. Scrolling to the end must reveal the entire final row. Short lists stay content-sized.

Default update guidance: keep playing while files are edited, then `/reload` after deployment. Do not ask for a full restart for updates to this existing addon, including diagnostics or added files in its manifest. A new addon folder needs a full restart. SavedVariables edits require the game to be closed; code edits do not.

Display estimated skillups rounded down to whole numbers; retain fractional scores internally for sorting. Diagnostics are automatic, local, bounded and read-only observers of client calls/events. Capture blocked/forbidden actions from any addon even outside crafting; preserve WoW's attribution and do not infer blame from a generic warning. Preserve the previous capture across reload so it can be inspected after a failed custom craft and a successful native craft. Do not claim a live bug is fixed based only on the simulated workflow.
