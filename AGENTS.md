# Professionator

WoW Forever addon, interface 16001. User's sketch defines the layout: left profession navigation, middle recipe list with search and ranking controls, right inputs → requirements → output and crafting controls.

The sketch defines structure, not a flat visual theme. Use WoW's native frame/button templates, game textures, gold headings and standard fonts. Harness previews approximate spacing and must not be presented as screenshots of native artwork.

Selected profession and recipe tabs, their connectors, the workspace and the detail panel share the same opaque near-black neutral fill (0.055 per RGB channel), using the native WHITE8X8 texture. Keep native borders and gold selection outlines; the window background, navigation, inactive rows and inset controls retain their native textures. Flat matching fills make the selected tabs and connected contents one continuous surface.

Keep the layout compact and content-sized. Recipe tiles always show the native item/recipe icon, skill-up icon, count and name on top, with left-aligned estimated skillups and right-aligned total/each coin prices below, without a dot separator. Sort buttons only change ordering, never the displayed information. Recipe tiles use 8-unit horizontal padding and 58-unit height. The selected recipe joins the detail panel with the same tab connector as profession navigation; keep text columns fixed, hide the connector when the selection is scrolled away, and extend the detail panel behind low selected rows. Do not reserve space for absent skill-up icons. Measure the full unbounded quantity text and round its width up with a small allowance; never truncate the bracketed count. No footer or slogan. Show actual known auction-price age in the detail header over the price columns. No cost-per-craft or margin line. A native gold minimap quest arrow, rotated downward, links materials to output without a hammer or requirement label; unmet station/tool requirements replace crafting controls with one red message and disappear when controls return.

Use a shared 12-unit inset around panels. Recipe tiles have smaller 6-unit gaps. The compact search uses a 6-unit inset and an internal placeholder. Sort choices are small inset buttons labelled Sort. The × Quantity checkbox, default checked, multiplies ranking by available crafts; unchecked ranks one craft. Never hide recipes based on materials. Persist the checkbox choice. Row counts, skillup estimates and total/each prices continue to describe available materials. Keep the columns compact; long recipe lists should scroll sooner on smaller screens instead of shrinking the text. Use `est.` for estimates, not a tilde, which renders poorly in the game's font.

Camping recipes belong in a separate Camping section below regular recipes under both sorts. Use larger gold-yellow section headings and an extra 8-unit gap above Camping when it follows visible regular recipes. Default to the first regular recipe when available; camping can be selected automatically when it is the only search result. Preserve explicit selections on refresh. Use the client's Camping category, not item-name guesses.

Within each section, sort first by the selected full-precision score, then by available craft quantity descending, then by recipe name and ID. Unknown auction prices remain below known prices. Give the bracketed quantity its own color: green when materials are available, red at zero. Recipe-name color and native skill-up arrows represent skill difficulty independently. Keep the existing `est. N skillups` text; the user declined a separate `no skillups` label.

Keep Blizzard's trade-skill session alive while hiding its visual window. Craft only on an explicit user click, revalidate profession, recipe, materials, requirements and combat at that moment. Never auto-buy, post or share messages. Preserve native window fallback.

Craft through a direct C_TradeSkillUI.CraftRecipe(recipeID, count) call on the hardware-click path, matching the user's formerly installed ProfessionBuddy 2.1.1 Forever implementation. Do not wrap the action in pcall/xpcall or schedule it. Observe rejection via client events; only spellcast-start confirms crafting, and matching spellcast-success events complete a batch. Watchdog timers must be tied to their request and must never craft.

The watchdog must respect native queued recasts between individual casts. A confirmed batch requires two separated idle observations before a silent stop; overdue timers start a fresh observation window so background throttling cannot beat queued cast events. Missing queue APIs fall back to the same idle grace. Real interruption/failure events still end the request immediately. Record timer recovery and queue state in diagnostics; never infer completed craft counts from elapsed time.

Left-clicking the minimap icon always opens Professionator. Right-click opens settings with a persistent replace-normal-window checkbox, defaulting on only when unset. Changes apply to the next normal profession open; an explicit original-window fallback lasts for that session only.

Use live C_TradeSkillUI data and Auctionator read-only APIs. Unknown prices are not zero. Vendor purchase prices and vendor sale values are distinct. Label skill ranking as heuristic when no exact chance is available. Show Create all total duration from spell cast time; refine total and remaining time from the live matching cast timestamps. Omit unknown timing rather than inventing a duration.

Quantity +/- buttons use native UIPanelSquareButton artwork, not squeezed wide red buttons, with fixed-size centered glyphs. Active crafting has its own textured panel anchored to the bottom right of the workspace, separated from the selected recipe details and never overlapping their tab connector. It stays visible when browsing other recipes, unmet requirements or empty search results. Show the active recipe's name and icon only when that recipe is not selected; capture this identity when the batch starts. Hide the entire panel when no batch is active. Idle duration previews and failures belong to the selected recipe details.

During confirmed crafting, center the remaining time in white with a dark shadow on the native gold progress bar. The bar is 28 units tall, leaving 7 units above and below its 14-unit countdown text; center it vertically beside the batch count and estimated total time. Progress covers the whole batch using the same timing model as the estimate; update its visual smoothly without rescanning recipes or initiating crafts. Hide the bar while starting without confirmation or missing timing, while keeping the active batch status visible.
